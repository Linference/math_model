# 01 — 深度审题清单

审题决定论文上限。目标：把"要解决什么、有什么约束、评委看什么"讲透，不建模、不写码。

## 逐问拆解表（每个小问填一行）
| 项 | 要点 |
|---|---|
| 输出类型 | 一个数 / 一张表 / 一个方案 / 一个证明 / 一段策略 |
| 显性约束 | 题面明说的限制、指标、目标 |
| 隐性约束 | 非负、整数、守恒、概率∈[0,1]、物理/工程可行、时间因果 |
| 给定数据 | 附件表格？字段？规模？单位？时间跨度？ |
| 需找数据 | 缺哪些，需联网或假设 |
| 依赖 | 是否依赖前一问的模型/结果 |

## 显性 vs 隐性要求
- 显性：直接读题面动词——"求""设计""评价""预测""优化""证明"。
- 隐性（最容易丢分）：
  - 单位一致性、量纲；
  - 变量取值范围（人数是整数、比例∈[0,1]）；
  - 守恒/平衡（质量、流量、预算）；
  - 边界与初始条件；
  - 现实可行性（负库存、超产能不合理）。

## 评分点推断
- 命题人最想看：**模型与问题匹配**、**结果正确且有验证**、**表达清晰**。
- 加分：创新方法、灵敏度/鲁棒性分析、对结果的深入解读、可推广性。
- 减分：假设牵强、推导跳步、结果无验证、图表不规范、摘要空洞。

## 常见陷阱
- 把开放题做成套模板，忽略题目特殊背景。
- 数据不做清洗直接用（异常值、缺失、量纲混用）。
- 上来就深度学习，样本不够→过拟合，评委质疑。
- 只报结果不报误差/置信度/灵敏度。
- 问题间本应耦合却各做各的。

## 产出
结构化审题报告（写入 REPORT.md 第 1 节），供 mm-modeler 直接使用。模糊处标"需假设/需联网确认"，不臆断。
