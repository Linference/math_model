## ⛔ 页面硬约束（优先级最高）

以下约束在编译 PDF 时必须逐页检查，不合格则退回修改：

### 1. 摘要页 —— 必须一页以内
- 摘要（含关键词）占满一页但**绝对禁止溢出到第二页**。
- 若文字太多 → 压缩语句、删空话；仍溢出 → `\zihao{5}`（五号字）或 `\small`（英文）。
- 若文字太少留下半页空白 → 补充量化结论（每个子问题至少一个数字），不得留大段空白。
- 模板默认 `\zihao{-4}`（小四），单页约可容纳 600-800 字中文或 350-500 词英文。

### 2. 目录页 —— 必须一页以内
- 目录默认 `tocdepth=2`（显示到 subsection）；若溢出 → 改为 `tocdepth=1`（只显示 section）。
- 仍溢出 → `tocdepth=0`（只显示 section 且无缩进）。
- 模板已用 `tocloft` 紧凑化目录间距（`cftbeforesecskip=2pt`）。
- 若目录不足半页 → 正常，目录之后 `\newpage` 进入正文即可。

### 3. 每页不允许过大空白
- 模板已启用 `\raggedbottom`（底部不对齐），防止 LaTeX 拉伸段落填满页面。
- 浮动体间距已紧凑化（`\floatsep=8pt`、`\textfloatsep=10pt`）。
- **禁止使用 `[H]` 强制浮动体**：用 `[htbp]` 让 LaTeX 自行优化位置，`[H]` 会在前一页留大片空白。
- 节末尾若只剩一行 → 用 `\needspace{3\baselineskip}` 把下一节标题推到下一页。
- 最后一段前用 `\needspace{3\baselineskip}` 防止孤行。

### 4. 不允许文字溢出页面
- 模板已设置 `\tolerance=800`、`\emergencystretch=1.5em`，减少 overfull hbox。
- 大图用 `width=\textwidth`（而非固定尺寸），避免超出页宽。
- 宽表用 `\small` 或 `\footnotesize` + `\setlength{\tabcolsep}{3pt}`。
- 超宽表用 `longtable` + `p{…}` 列规格，或 `resizebox{\textwidth}{!}{…}`。
- 公式过长 → 用 `split` / `multline` / `align` 环境换行。

### 5. 浮动体管理
- 每节末尾加 `\FloatBarrier`（placeins 宏包）阻止图表漂移到下一节。
- 大图若撑破当前页 → `\afterpage{\begin{figure}[H]…}` 延迟到下一页顶部。
- 单独一页的大图 → `\begin{figure}[p]` 独占一浮动页。

## 国赛论文结构（标准，已增强）

1. 摘要（单独一页，评分命脉）
2. 问题重述
3. 问题分析
4. 模型假设与局限性讨论（**每条假设含依据+局限性+放宽后果**）
5. 符号说明
6. 模型的建立与求解（按问分小节）
7. **模型对比验证**（与 1-2 个基准/消融模型多指标对比）
8. 灵敏度分析 / 误差分析
9. 模型的评价与推广（**创新点+深度缺点分析+推广**）
10. 参考文献
11. 附录（核心代码、补充图表）

## 摘要写法（最关键）

每问一段，写清：**用什么模型 + 怎么求解 + 关键量化结果**。
> 例：针对问题一，建立整数规划模型，采用分支定界求解，得到最优方案，总成本降低 **18.3%**，运行时间 **0.7s**。

忌空话（"本文进行了深入研究"）。摘要要让评委只读它就知道你做了什么、结果多少。关键词 4-5 个。

## 写作要点

- 公式用 `equation/align` 并编号；重要变量在符号说明表定义。
- 图 `figure[htbp]` + `caption` + `label`，正文 `\ref` 引用并解读；表用三线表 `booktabs`。
- 假设要合理且**服务于建模**，每条假设给一句依据。
- 结果必须有验证（灵敏度/交叉验证/误差/对照）。
- 语言客观严谨，逻辑连接词清楚；中文赛用中文，MCM 用英文（美赛还需 Summary Sheet）。
- 代码入附录用 `\lstinputlisting`。

### ⛔ 审题结论贯穿原则

写作时 `mm-writer` **必须**对照阶段 1 审题报告逐条落实：
- 审题报告中的每小问 → 论文中对应独立小节（不得合并、不得遗漏）
- 审题报告中的隐性约束 → 论文中显式说明如何处理
- 审题报告中的陷阱 → 论文中注释如何规避
- 审题报告中的评分点 → 论文中重点展示相关内容
- 写作完成后逐条自检：审题报告中的每项要求在论文中是否有对应落点

### ⛔ 思考链保留原则

以下内容**不可**在论文中省略或浓缩：
- 为什么选这个方法而不是其他方法（对比依据）
- 算法关键参数的取值依据（不能写"凭经验选取"）
- 结果的含义解读（不能只放图表不说话）
- 灵敏度分析的结论（不只是"模型稳健"，要说"在什么范围内稳健、超出什么范围失效"）
- 每个数字的来源（可以直接追溯到代码输出）

## ⛔ 四项深度要求（高分 vs 及格的分水岭）

### 1. 假设局限性深度讨论

**不允许**只写"假设系统处于稳态""假设数据无噪声"——必须讨论：
- **每条假设的依据**：为什么可以这样假设？（引用文献/实际经验/数据特征）
- **放宽后果的量化估计**：若假设不成立，误差量级多大？偏差方向？结论是否逆转？
- **适用边界**：在什么条件下假设失效？给出具体阈值或场景。
- **补救方案**：若放宽该假设，可用什么方法修正？

> 示例（不要这样写）："假设人口均匀分布。"（太浅）
> 
> 示例（应该这样写）："假设人口均匀分布。依据：研究区域为高密度城区，人口密度方差系数 < 0.15（来源：第七次人口普查街道级数据）。局限性：若应用于城乡结合部（密度方差 > 0.5），该假设导致设施选址偏差约 +12%~18%（设施偏向中心区域）。此时应用人口加权 Voronoi 修正。"

### 2. 对比模型验证

**必须**设置至少 1-2 个对比模型，用同样数据跑出结果，多指标对比，证明你的模型不是"随便选的"：
- **基准模型**：经典/简单方法（如线性回归 vs 你的非线性模型、贪心 vs 你的优化）
- **消融模型**：去掉你的某个创新组件，验证该组件的贡献
- **对比维度**：至少 3 个指标（精度/效率/稳健性/可解释性 等）
- **可视化**：对比表（三线表）+ 雷达图 `radar_chart` 多维度一目了然

> 示例表头：模型 | RMSE | MAE | R² | 运行时间(s) | 稳健性评分

### 3. 创新点包装

创新不必是"发明新算法"——以下都算创新，要在摘要和评价中显式声明：
- **方法组合创新**：将 A 方法与 B 方法首次结合用于本问题
- **改进创新**：对标准方法做了针对性改进（如加入约束/自适应参数）
- **应用创新**：将某领域方法迁移到新领域
- **建模视角创新**：从新角度定义问题（如从博弈而非优化角度）
- 在"模型优点"中至少列出 1 条理论创新 + 1 条方法创新

### 4. 多指标优化与评估

不要只盯一个指标——单指标容易过拟合且显得分析单薄：
- **每个模型至少报告 3 个指标**（如精度 + 效率 + 稳健性）
- **指标选择原则**：一个反映"多好"（精度/误差类）、一个反映"多快"（时间/复杂度类）、一个反映"多稳"（灵敏度/方差类）
- **综合评分**：若有多个模型对比，给出加权综合得分（权重用熵权法/AHP）
- **指标冲突分析**：若两个指标不能兼得（如精度 vs 速度），用 Pareto 前沿讨论权衡

## 编译、页面检查与 PDF 版本留存

```bash
# 编译（自动留存版本到 paper/versions/main_vXXX.pdf）
python <skill>/scripts/compile.py paper/main.tex

# 编译后打开 PDF，逐页检查：
# ① 摘要是否 1 页内？（溢出→压缩；<半页→补量化结论）
# ② 目录是否 1 页内？（溢出→\setcounter{tocdepth}{1}）
# ③ 每页底部是否有 ≥3cm 空白？（有→检查 [H] 浮动体→改为 [htbp]）
# ④ 是否有文字突出页边距？（有→公式换行/图表缩宽/\emergencystretch）
```

### ⛔ PDF 版本留存机制

`compile.py` 每次成功编译后自动把 PDF 复制到 `paper/versions/` 目录：
- `main_v000.pdf` — 阶段 6 初稿（审稿前基线）
- `main_v001.pdf` — 审稿第 1 轮修改后
- `main_v002.pdf` — 审稿第 2 轮修改后
- ……
- `main.pdf` — 始终为最新版

**规则**：
- 每次编译自动递增版本号，无需手动管理
- 阶段 7 每轮修改后必须重新编译（触发版本留存）
- 所有版本提交到 git，确保可回溯任意阶段的论文状态
- `paper/versions/` 目录加入 `.gitignore` 白名单（不被排除）

失败读 `.log`；常见坑：缺宏包(MiKTeX 会提示装)、中文未用 xelatex、图片路径。
