# 08 — 阶段验证协议

每个阶段完成后必须执行独立验证。验证不通过 = 退回该阶段重做，不得前进。

---

## 验证总则

1. **验证独立于执行**：执行智能体和验证智能体不能是同一个（阶段 4-7 强制用 mm-verifier 执行验证）
2. **验证必须落盘**：验证结果写入 REPORT.md 对应小节末尾
3. **验证失败必须退回**：不允许"验证不通过但先前进后面再修"
4. **验证项全部通过才算完成**：任一不通过 = 该阶段未完成

---

## 阶段 1 验证：审题完整性

**验证人**：人工 + mm-verifier 辅助核对

### 1.1 问题覆盖检查

```
检查项：problem.md 中的小问数 == REPORT.md §1 中的拆解数
方法：数 problem.md 中的问号/数字编号，对比审题报告中的子问题数
不通过：拆解数 < 问数 → 补拆缺失小问
```

### 1.2 隐性约束检查

```
检查项：审题报告 §1.3 隐性约束 ≥ 3 条（几乎所有赛题都有至少 3 条隐性约束）
方法：逐条检查每条隐性约束是否有推导依据
不通过：少于 3 条 或 某条无推导依据 → 补推
```

### 1.3 问题类型判定

```
检查项：REPORT.md §1.7 有问题类型判定，且有 ≥3 条判定依据
方法：人工判断类型是否合理（对照赛题实际内容）
不通过：类型判定明显错误 → 重判
类型清单：优化类 / 评价类 / 预测类 / 机理类 / 混合类
```

### 1.4 审题深度

```
检查项：REPORT.md §1 总字数 ≥ 2000 字
方法：大致估算（中文约 2000 字 ≈ 3-4 页）
不通过：明显偏短（< 1000 字） → 展开细节
```

## 阶段 2 验证：方法选型合理性

**验证人**：mm-reasoner

### 2.1 方法-问题匹配

```
检查项：阶段 2 方案表中的方法是否与 §1.7 问题类型一致
对照表：
  优化类 → LP/IP/NLP/启发式/变分
  评价类 → AHP/TOPSIS/熵权/灰色/模糊
  预测类 → 时序/回归/ML/GM(1,1)
  机理类 → ODE/PDE/系统动力学/元胞自动机
  混合类 → 各子问题分别匹配

不通过：方法明显与问题类型不匹配 → 重选
```

### 2.2 ML/DL 决策审计

```
检查项：每问的 ML/DL 判定栏有 ≥50 字的理由
通过标准：理由不能是"不需要"三个字，必须讨论样本量/可解释性/确定性
不通过：理由敷衍 → 补理由
```

### 2.3 算法可行性预审

```
检查项：方案表中每个方法标注了：
  - 计算复杂度 (O(n²) / ...)
  - 收敛条件 / 适用条件
  - 已知坑点

不通过：缺少任一标注 → 补标注
```

## 阶段 4 验证：算法正确性（⛔ 最关键）

**验证人**：mm-verifier（强制，不可由 mm-coder 自验）

### 4.1 代码可运行

```bash
# 逐文件执行，确认无报错
for f in code/solve_q*.py; do
    echo "=== Running $f ==="
    python "$f" || { echo "FAILED: $f"; exit 1; }
done
echo "ALL PASSED"
```

### 4.2 输出有具体数值

```
检查项：每个 solve_q*.py 的 stdout 中包含 ≥3 个具体数字
方法：逐文件运行并检查输出
不通过：输出中出现 "最优解是 x" 等占位符 → 确保代码真实跑通
```

### 4.3 边界条件测试

```python
# 每个 solve_q*.py 应能处理极端输入
# 检查点：输入=0、输入=极大值、输入=空数组时程序不崩溃
```

### 4.4 量纲一致性

```
检查项：所有输出数字带单位，且单位体系统一
例如：全用 kgCO2e，不能混用 tCO2e 和 kgCO2e
不通过：混用单位 → 统一
```

### 4.5 公式一致性审计

```
检查项：代码中的公式实现 vs REPORT.md §2 方案表中的公式
逐项核对：
  - 变量名是否一致
  - 参数含义是否一致
  - 正负号是否正确
  - 约束条件是否完整实现

不通过：不一致 → 修正代码或更新方案表
```

### 4.6 随机种子

```
检查项：所有含随机性的代码含 np.random.seed(N)
方法：grep "random.seed" code/solve_*.py
不通过：缺失 → 补种子
```

### 4.7 关键数字可追溯

```
检查项：代码输出中的每个关键数字对应到具体变量名和行号
记录格式：
  英格尔伍德 TOPSIS 得分 0.7637 → solve_q3a.py:142, 变量 topsis_scores[0]
  电网碳因子权重 0.2915    → solve_q2.py:88,   变量 global_weights[0]

不通过：有数字无法追溯 → 确保每个数字有明确出处
```

## 阶段 5 验证：图表覆盖

**验证人**：mm-verifier

### 5.1 图数量检查

```bash
# PNG 数量 ≥ REPORT.md §2 模型数

echo "模型数≈$model_count, 图数=$png_count"
```
