# 07 — 多智能体对抗审稿协议

核心创新：多个 AI 子智能体各司其职，交叉审稿、互相挑战，用对抗机制逼出最高质量。由 `workflows/adversarial-review.js` 驱动。

目标：将基线水平通常在 5.0--6.0 的初稿，经 2--4 轮对抗审稿提升至 7.5+（省一等奖级别），每条弱点必须**可定位、可执行修法**。

---

## 一、三角色分工与职责边界

### 1.1 角色矩阵

| 角色 | agentType | 核心职责 | 审查聚焦域 | 输出物 |
|---|---|---|---|---|
| 审稿人 | `mm-reviewer` | 建模合理性 + 创新性 + 表达规范 | 模型选型逻辑、假设验证、创新真实性、论文结构性 | 五维度评分 + 按严重度排序的弱点清单 + verdict |
| 验证者 | `mm-verifier` | 数值准确性 + 量纲/边界/单位 | 计算结果可复现性、量纲一致性、边界条件检验、数字可追溯性 | 逐项检查清单（pass/fail）+ 发现的数值错误 + needMoreExperiments 标记 |
| 推理者 | `mm-reasoner` | 公式推导审计 + 数学严谨性 | 每步推导的正确性、定理引用的恰当性、收敛性/存在性证明、符号一致性 | 推导步进审计报告 + 发现的逻辑漏洞 + 修正建议 |

### 1.2 三角色协作模式

三角色**并行独立评审**，评审期间不互相通信（防止群体思维）。评审结束后，由工作流引擎聚合三份评审报告，按以下优先级合并弱点清单：

- 任一角色标记为 **High** 的弱点 → 全局 High（最严重者优先）
- 两个或以上角色独立发现的同一弱点 → 严重度升级一级
- 仅一个角色发现的 Medium/Low 弱点 → 维持原严重度

### 1.3 每个角色的评分维度权重

三个角色的评分不能简单平均——各角色对自己聚焦的维度有更高的权重和发言权。

| 维度 | 审稿人权重 | 验证者权重 | 推理者权重 | 聚合方式 |
|---|---|---|---|---|
| modeling (建模合理性) | **50%** | 20% | 30% | 加权平均 |
| rigor (数学严谨性) | 20% | 30% | **50%** | 加权平均 |
| results (结果与验证) | 20% | **60%** | 20% | 加权平均 |
| writing (表达规范) | **70%** | 10% | 20% | 加权平均 |
| innovation (创新性) | **60%** | 10% | 30% | 加权平均 |

聚合公式：
```
维度分数_d = Σ(角色评分_d × 角色权重_d) / Σ(角色权重_d)
综合分 = Σ(维度分数_d × 维度权重_d)
```

## 二、五维度评分细则（含具体分档锚点）

每个维度 0--10 分，每 2 分一档。评审时必须给出具体分数（不得给区间），并附至少一句话的证据说明。

### 2.1 建模合理性 (modeling)

| 分数 | 分档名称 | 特征描述 | 典型论文示例 |
|---|---|---|---|
| **0--2** | 致命缺陷 | 模型类型与问题完全不匹配（如优化问题用纯描述统计）；关键约束全部遗漏；假设明显违背物理/经济常识 | 要求预测销量却只做了描述性统计和画柱状图 |
| **3--4** | 勉强可用 | 模型类型方向正确但假设牵强（如"各指标相互独立"无视已知相关性）；只提了一个模型，未论证为何选它 | 用层次分析法但未说明为什么不用熵权法/TOPSIS |
| **5--6** | 基本合理 | 模型适用，假设尚可接受（至少无硬伤）；有简单的方法选型说明；但对假设的局限性讨论不足 | 用微分方程建模传染病，假设均匀混合但未讨论该假设的局限性 |
| **7--8** | 扎实合理 | 模型精准对应问题结构；假设逐条给出依据或文献支撑；有"为什么选A不选B/C"的对比段落；对关键假设做了合理性检验 | 建模时对比了3种回归方法，用VIF排除多重共线性，用残差图验证假设 |
| **9--10** | 典范级 | 在7--8基础上，模型有优雅的简化（抓住本质舍弃噪音），假设条件有灵敏度验证（证明放宽假设后结论仍稳健） | 用NS方程建模但通过量纲分析证明了某些项可忽略，且验证了忽略后的误差<3% |

### 2.2 数学严谨性 (rigor)

| 分数 | 分档名称 | 特征描述 | 典型论文示例 |
|---|---|---|---|
| **0--2** | 致命缺陷 | 公式有严重错误（符号张冠李戴、量纲矛盾、除以零）；关键推导步骤缺失且无法补全；定理引用错误 | 矩阵乘法维度不匹配，或概率密度积分为2.3 |
| **3--4** | 多处漏洞 | 推导有跳步，从前提跳到结论缺中间过程；有"显然""易证"跳过不显然的步骤；符号前后不一致 | 声称"显然收敛"但函数非凸，或前文用x_i后文用X_i混淆 |
| **5--6** | 基本完整 | 主要推导链完整，关键公式含义清楚，无算术错误；但存在以下问题之一：缺收敛性讨论（优化题）、缺置信区间（统计题）、缺一致性检验（AHP题） | 微分方程模型求解正确但未讨论解的稳定性和参数敏感性 |
| **7--8** | 严谨 | 所有公式编号可追溯，推导无跳步；优化题交代了凸性/收敛性；统计题报告了p值/置信区间；AHP题CR<0.1且报告了λ_max/CI/CR | 每步推导有明确的前置引用，关键定理的适用条件被明确验证 |
| **9--10** | 典范级 | 在7--8基础上，关键结论有严格证明（最优性、存在唯一性）；推导过程有自查（反向代入验证）；对所用数学工具的边界条件有明确讨论 | 证明了目标函数的凸性→全局最优，用KKT条件验证最优解，给出了误差界 |

**具体检查清单**（评审时必须逐条核查）：
- [ ] 所有公式中的变量在符号说明表中定义
- [ ] 所有矩阵/向量维度在上下文一致
- [ ] 所有求和/积分范围明确
- [ ] 所有比值分子分母量纲一致
- [ ] AHP类：CR < 0.1 且报告了 λ_max、CI、CR
- [ ] 优化类：交代了凸性/收敛性/最优性条件
- [ ] 统计类：报告了 p 值/置信区间/效应量
- [ ] 微分方程类：交代了初边值条件、解的存在唯一性
- [ ] 图论/网络类：节点/边/权重的数学定义明确
- [ ] 概率模型：概率分布选型有依据（Q-Q图/K-S检验）

### 2.3 结果与验证充分性 (results)

| 分数 | 分档名称 | 特征描述 | 典型论文示例 |
|---|---|---|---|
| **0--2** | 无验证 | 结果无任何验证；数值明显不合理（概率>1、效率>100%）；前后数据自相矛盾 | 产出结果但未做任何灵敏度分析、交叉验证或对比实验 |
| **3--4** | 象征性验证 | 只做了一种验证且敷衍（如灵敏度只扰动了一个参数±5%）；验证与结论脱节 | 只画了一张参数变化图，未分析变化幅度是否可接受 |
| **5--6** | 基本验证 | 有至少一种有效验证；灵敏度分析覆盖关键参数；但缺交叉验证/对照实验/误差归因 | 做了±20%参数扰动但未解释为何某些参数影响特别大 |
| **7--8** | 充分验证 | ≥2种验证方式；灵敏度分析系统（多参数、合理范围）；有与基准方法/模型的对照；报告了误差来源 | 灵敏度+交叉验证+对照实验，结果稳健性得到证实 |
| **9--10** | 典范级 | ≥3种验证方式；灵敏度分析揭示了参数影响的结构性规律（如阈值效应）；对照证明了方法优势且量化了优势幅度；深入讨论了不确定性的来源和传播 | 不仅验证了结果正确，还通过灵敏度分析发现了关键参数的临界值，并由此提出了实践建议 |

**验证方式清单（评审时标记已使用的验证方式）**：
| 验证类型 | 说明 | 适用场景 |
|---|---|---|
| 灵敏度分析 | 关键参数±10%/±20%/±50%扰动，观察输出变化 | 所有模型 |
| 交叉验证 | k-fold / LOOCV / 训练-测试分离 | ML/统计模型 |
| 对照实验 | 与基准方法/基线模型/简单启发式对比 | 提出新方法时 |
| 误差分析 | 报告MAE/MSE/MAPE，分解偏差-方差 | 预测/拟合模型 |
| 极端情况检验 | 输入取极值/边界值/退化情况，验证结果合理 | 所有模型 |
| 蒙特卡洛模拟 | 参数随机采样，输出分布分析 | 随机性模型 |
| 实际数据回测 | 用历史数据验证预测准确性 | 时序预测 |
| 量纲验证 | 独立验证所有公式的量纲一致性 | 物理/工程模型 |

### 2.4 表达与图表规范 (writing)

| 分数 | 分档名称 | 特征描述 | 典型论文示例 |
|---|---|---|---|
| **0--2** | 难以阅读 | 摘要无量化结果（全是空话）；图表混乱无编号；符号从未定义；段落无逻辑衔接 | "本文对XX问题进行了深入研究，取得了较好的结果"——读完不知道具体做了什么 |
| **3--4** | 有明显缺陷 | 摘要缺关键数字；部分图表无解读文字；符号说明表不完整；参考文献格式混杂 | 图放上去了但正文从未引用，或引用了但未解读图传达了什么意思 |
| **5--6** | 基本规范 | 摘要含若干数字；图表有编号和caption；符号基本有定义；但"信息密度"不够（如摘要仍有套话、图表解读过于浅显） | 结构完整但表达冗长，关键信息淹没在大段文字中 |
| **7--8** | 表达清晰 | 摘要每问量化（读完知做了什么+结果多少）；每图被正文引用且有1-2句实质解读；表格用三线表；参考文献格式统一；行文有逻辑连接词 | 读完摘要即可判断论文水平，图表自包含（看图和caption就能理解） |
| **9--10** | 典范级 | 在7--8基础上，摘要即论文名片（200字内说清4问模型+结果）；图表有"视觉叙事"（读者看图顺序即理解逻辑）；行文精炼无废字；信息可视化选择恰当（该用热力图不用表格） | 摘要读完可直接用于评审判断，图表设计直接可用于展示 |

**具体检查清单**：
- [ ] 摘要含 ≥4 个具体数字（每问至少1个）
- [ ] 每张图在正文被 `\ref` 引用且有 1--2 句实质解读
- [ ] 所有符号在符号说明表定义
- [ ] 表格用三线表（booktabs）
- [ ] 参考文献格式统一（至少作者、标题、出处三项齐全）
- [ ] 章节编号规范（不超过三级：1 → 1.1 → 1.1.1）
- [ ] 公式编号连续无跳跃
- [ ] 无"进行了深入研究""取得了较好结果""具有一定的参考价值"等空话

### 2.5 创新性 (innovation)

| 分数 | 分档名称 | 特征描述 | 典型论文示例 |
|---|---|---|---|
| **0--2** | 无创新 | 纯套模板，方法与问题无适配；方法全是课本标准解法，无任何改进 | 评价类问题直接用AHP 1--9标度，无任何针对问题特点的调整 |
| **3--4** | 伪创新 | 声称创新但实际是换名字或小修小改；创新声明无对比验证 | "本文提出了改进的XX模型"——实际只是改了参数默认值 |
| **5--6** | 有适配 | 标准方法针对问题特点做了合理适配（如自定义指标、加权策略），但适配本身无太大新意 | 把通用评价指标体系替换为针对本问题的特定指标 |
| **7--8** | 有改进 | 对现有方法有明确的改进（如改进算法步骤、组合两种方法互补），且通过对比证明了改进有效 | "将熵权法与TOPSIS结合，先用熵权确定客观权重再用TOPSIS排序，对比单一AHP精度提升8%" |
| **9--10** | 真创新 | 方法原创或组合巧妙，视角独到，创新解决了实际问题且被充分验证；或引入了新的数学工具处理本领域新问题 | 将图神经网络引入传统微分方程建模，用物理信息约束提升了小样本下的预测精度 |

## 四、对抗审稿完整流程

### 4.1 阶段流程总览

```
阶段 A: Algorithm Audit（自动化算法审计）
   → 运行 verify_results.py --stage 4
   → 检查：代码可运行性 + 公式一致性 + 数字可追溯 + 量纲一致性
   → 若 FAIL → 中止审稿，退回阶段 4 修复
   → ✅ 通过 → 进入基线评审

阶段 B: Baseline（基线评审）
   → 编译基线 PDF 并留存版本 (main_v000.pdf)
   → [审稿人 ∥ 验证者 ∥ 推理者] 并行对抗打分 + 弱点清单
   → 按角色权重聚合五维度分数
   → 聚合弱点清单（去重+升级规则）

阶段 C: Revise + Re-review（修改 + 复评循环）
   → 若综合分 < 目标分(默认7.5) 且 当前轮次 ≤ 最大轮次(默认4)：
        (1) 写作者读取所有评审报告
        (2) 按 High → Medium → Low 顺序逐条修改
        (3) 对 needMoreExperiments=true 的条目自动补充实验
        (4) 写作者输出修改日志（逐条回应）
        (5) 重新编译并留存版本 PDF (main_v001.pdf → main_v004.pdf)
        (6) 三角色复评（仅重评已修改的章节）
   → 达标(综合分≥7.5) 或用尽 4 轮 → 进入阶段 D

阶段 D: Final（终版编译与放行判定）
   → 编译终版 PDF
   → 验证 High 级别弱点 ≤ 1 个
   → 验证综合分 ≥ 7.0（即使未达7.5目标，至少保证省二水平）
   → 若未通过放行判定 → 标记为"未达标"，返回最终评分和残留弱点
```

### 4.2 修改-复评协议（写作者必须遵守）

#### 逐条回应格式

写作者收到评审报告后，必须对**每条弱点（无论高低）**输出以下格式的回应：

```
## 第X轮修改日志

### 对审稿人问题的回应
1. [原问题摘要] — 原严重度: 高
   → 处理: [已修改 / 部分修改 / 未修改]
   → 修改内容: [具体改了什么，新文本/新图/新公式的位置]
   → (若未修改) 理由: [如：与后续问题冲突 / 超出数据支持范围 / 需要额外实验时间]

2. [原问题摘要] — 原严重度: 中
   → ...

### 对验证者问题的回应
...

### 对推理者问题的回应
...

### 本轮修改总结
- 共收到弱点: X个 (High: Y, Medium: Z, Low: W)
- 已修改: X_1个
- 部分修改: X_2个
- 未修改: X_3个 (理由汇总)
- 新增实验: [列举]
```

#### 复评规则

- 复评时**仅重评已修改的章节/维度**，未修改部分沿用上轮评分
- 若写作者标记"已修改"但评审认为修改不到位 → 该弱点维持原严重度
- 若写作者标记"未修改"且给出了合理理由 → 该弱点降一级（如高→中），但不得消除
- 无理由的"未修改" → 维持原严重度

#### 收敛条件与停滞处理

**正常收敛条件**（满足任一即停止循环）：
- 综合分 ≥ 目标分（默认7.5），且 High 弱点 ≤ 1 个
- 已用完最大轮次（默认4轮）

**停滞判定**（连续3轮满足以下任一）：
- 综合分提升 < 0.3
- High 弱点数量未减少
- 三个角色中有两个给出 verdict=reject

**停滞处理**：
1. 写作者总结残留问题，标注"超出当前能力/数据范围"
2. 论文标注"未达标"及最高得分
3. 输出给用户，建议人工介入或接受当前水平

## 五、自动补充实验触发

### 5.1 触发条件

任一评审 `needMoreExperiments=true` 即触发。常见触发场景：

| 触发场景 | 具体判据 | 补充实验类型 |
|---|---|---|
| 结果验证单薄 | 仅有1种验证或无验证 | 补做灵敏度分析、对照实验或交叉验证 |
| 灵敏度分析不足 | 只扰动了一个参数且扰动范围<±10% | 补做多参数、宽范围的系统灵敏度分析 |
| 缺对照/基线 | 未与任何基准方法对比 | 实现一个简单基准方法并对比 |
| 极端情况未检验 | 未讨论边界/退化情况 | 补做极端参数下的模型行为检验 |
| 结论过度推广 | 在小数据集上得出的结论声称普适 | 补做不同数据子集/场景下的验证 |

### 5.2 补充实验规范

写作者需：
1. 生成新图表放入 `figures/` 目录
2. 在论文中新增或扩充"模型验证"或"灵敏度分析"章节
3. 在修改日志中标注新增实验的位置

## 六、常见论文弱点库（20+条）

按五维度分类，每条含检测方法与修复建议。评审时作为检查备忘录使用。

### 6.1 建模合理性 (modeling) 弱点

| # | 弱点名称 | 检测方法 | 严重度 | 修复建议 |
|---|---|---|---|---|
| M1 | 模型选型无对比论证 | 搜索"本文采用""本文选择"附近是否有备选方案讨论 | 高 | 增写一段对比分析：列出2--3种备选方法，说明各自优劣，给出选择理由 |
| M2 | 假设无依据/无验证 | 搜索"假设"一词，检查每条假设是否有文献/数据/常识支撑 | 高 | 为每条关键假设增写：①提出依据；②若可能，用数据验证；③讨论假设不成立时的影响 |
| M3 | 关键约束遗漏 | 对照问题重述，检查模型是否覆盖了所有硬约束 | 高 | 逐条对照问题描述，补全遗漏约束到模型公式中 |
| M4 | 模型过于简化 | 检查是否忽略了问题描述中明确提及的重要因素 | 中 | 分析被忽略因素的影响，论证可以忽略或将其纳入模型 |
| M5 | 模型与问题类型不匹配 | 检查：优化问题是否用了优化方法？分类问题是否用了分类方法？ | 高 | 重新审视问题本质，确保方法类型对应 |
| M6 | 指标体系构建缺依据 | 评价类问题：搜索指标选取是否有文献/专家依据 | 中 | 引用相关文献支撑指标选择，或用相关性分析精简指标 |

### 6.2 数学严谨性 (rigor) 弱点

| # | 弱点名称 | 检测方法 | 严重度 | 修复建议 |
|---|---|---|---|---|
| R1 | 公式推导有跳跃 | 逐行检查推导链，标记"显然""易证"背后的跳步 | 高 | 补全中间步骤，或将跳步改为详细推导（可移入附录） |
| R2 | 量纲/维度不一致 | 独立检查所有公式的量纲（物理模型）或矩阵维度（代数模型） | 高 | 修正量纲错误，在符号说明表中明确所有变量的量纲和维度 |
| R3 | 符号前后不一致 | 全文搜索每个符号，检查是否始终表示同一含义 | 中 | 统一符号，建立符号命名规范，更新符号说明表 |
| R4 | 收敛性/最优性未讨论 | 优化模型：搜索"收敛""最优""全局"等词是否存在 | 中 | 增写收敛性讨论（至少说明算法为什么收敛）或最优性条件验证 |
| R5 | 统计推断缺p值/置信区间 | 统计模型：搜索结果部分是否有区间估计或假设检验 | 中 | 报告置信区间和/或p值，不要只报告点估计 |
| R6 | AHP一致性检验缺失 | 检查是否报告了λ_max, CI, CR | 高 | 计算并报告一致性指标，CR≥0.1则需调整判断矩阵 |

### 6.3 结果与验证 (results) 弱点

| # | 弱点名称 | 检测方法 | 严重度 | 修复建议 |
|---|---|---|---|---|
| V1 | 灵敏度分析缺失或敷衍 | 搜索"灵敏度""敏感性""鲁棒"，检查是否有系统分析 | 高 | 识别3--5个关键参数，做±20%扰动，分析输出变化幅度 |
| V2 | 无对照/基准对比 | 检查是否与任何现有方法/简单基线做了对比 | 中 | 实现至少一种基准方法并对比关键指标 |
| V3 | 结果分析只有描述无解释 | 检查结果段落：是只说"XX=YY"还是解释了"为什么XX=YY" | 中 | 对每个关键结果增加1--2句解释：为什么会这样？反映了什么规律？ |
| V4 | 数值不可追溯 | 随机抽取论文中3个关键数字，检查能否追溯到代码输出 | 高 | 在代码注释中标注对应的论文公式/段落编号，确保可追溯 |
| V5 | 误差来源未分析 | 搜索"误差""偏差""不确定性"，检查是否有归因分析 | 中 | 增写误差分析：识别主要误差来源，估计各来源的量级 |

### 6.4 表达规范 (writing) 弱点

| # | 弱点名称 | 检测方法 | 严重度 | 修复建议 |
|---|---|---|---|---|
| W1 | 摘要无量化结果 | 审查摘要：是否包含≥4个具体数字 | 高 | 为每问的答案增写至少1个具体关键数值 |
| W2 | 图表与正文数据不一致 | 交叉检查：从正文抽取3个数字，与对应图表核对 | 高 | 建立数据溯源表，确保正文数字与图表/代码输出一致 |
| W3 | 图片无解读 | 检查每张图是否被"如图X所示"引用且后有1--2句含义解读 | 中 | 为每张图增写1--2句解读：图中展示了什么规律/趋势/异常 |
| W4 | 符号说明表不完整 | 遍历所有公式中的符号，检查是否全部在符号说明表中 | 中 | 补全符号说明表，按字母/类型排序 |
| W5 | 结论超出数据支持 | 检查结论中的推广性表述（"普适""一般性""充分证明"） | 中 | 在结论中增加限定词（"在本文条件下""在当前数据集上"） |

### 6.5 创新性 (innovation) 弱点

| # | 弱点名称 | 检测方法 | 严重度 | 修复建议 |
|---|---|---|---|---|
| I1 | 伪创新 | 检查"创新""改进""提出"等词，看是否有实质性的方法改动 | 中 | 若确实无实质创新，诚实定位为"应用创新"而非"方法创新" |
| I2 | 创新未验证优势 | 检查创新声明附近是否有对比实验证明优势 | 高 | 补充对比实验，量化创新带来的性能提升 |

## 七、PDF 版本留存

对抗审稿每轮修改后都会自动调用 `compile.py` 编译并留存版本 PDF 到 `paper/versions/`：
- 基线版（审稿前）：`main_v000.pdf`
- 每轮修改版：`main_v001.pdf` → `main_vNNN.pdf`
- 终版：`main_final.pdf`

所有版本可通过文件名序号追溯论文演进过程。复评时可以对比前后版本，确认修改确实被应用。

## 八、调用接口

```
Workflow({ scriptPath: "<skill>/workflows/adversarial-review.js",
  args: {
    draftPath: "<slug>/paper/main.tex",
    lang: "zh",
    targetScore: 7.5,
    maxRounds: 4,
    projectRoot: "<skill>",
    dataContext: "<关键结果数值>",
    skipAlgorithmAudit: false
  }
})
```

**参数说明**：

| 参数 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| draftPath | string | (必填) | 待审论文 main.tex 的路径 |
| lang | "zh" / "en" | "zh" | 论文语言，影响评审语言和检查项侧重 |
| targetScore | number | 7.5 | 目标综合分，达此分即停止循环 |
| maxRounds | number | 4 | 最大修改-复评轮次 |
| projectRoot | string | (必填) | 技能根目录 |
| dataContext | string | "" | 关键数据上下文（如"最优值=42.7, 误差=3.2%"），供评审交叉核对 |
| skipAlgorithmAudit | boolean | false | 是否跳过阶段A的自动化审计（仅用于已验证过的快速复评） |

**返回值**：
```
{
  finalScore: number,           // 终版综合分
  roundScores: number[],        // 每轮评分
  residualHighIssues: Issue[],  // 残留高严重度弱点
  dimensionScores: {            // 终版五维度分
    modeling: number,
    rigor: number,
    results: number,
    writing: number,
    innovation: number
  },
  convergenceStatus: "converged" | "max_rounds" | "stuck",
  versionHistory: string[]      // PDF版本文件路径列表
}
```
