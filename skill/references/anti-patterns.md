## 1 建模逻辑错误

### 1.1 过拟合（Overfitting）

**症状**
- 训练集上拟合精度极高（R² > 0.99），但测试集上表现骤降（R² < 0.5 甚至为负）
- 模型曲线经过每个训练数据点，但中间剧烈振荡
- 模型中参数数量接近或超过样本数量
- 模型使用高阶多项式（≥5 阶）拟合本可线性描述的规律

**真实案例**
2023 年全国赛 B 题某参赛队，用 12 阶多项式拟合仅有 8 个数据点的温升曲线，训练 R² = 0.9998，但预测 2050 年温升为 -15°C，违反物理常识。评委直接判为"模型不可靠"，扣 20 分以上。

**诊断方法**
- 做 K 折交叉验证（K=5 或 10），训练集与验证集 R² 差距 > 0.15 即为过拟合
- 画残差图：训练点的残差是否均匀分布在 0 两侧，测试点的残差是否系统偏大
- 计算 AIC/BIC：参数过多的模型会被惩罚项拉高
- 若数据点 ≤ 20，限制多项式阶数 ≤ 3

**修复方案**
- 优先使用数据量允许的最简单模型（Occam's razor）：点数 n → 多项式阶数 ≤ n/3
- 引入正则化：L2（Ridge）或 L1（Lasso）惩罚项，α 从 0.001 试到 1.0
- 改用非参数回归（LOESS、核回归）或光滑样条（smoothing spline），控制 df ≤ 5
- 若必须复杂模型（如神经网络），增加 dropout（rate=0.2~0.5）和早停（patience=10~20）

### 1.2 因果混淆（Causality Confusion）

**症状**
- 论文中出现"A 与 B 高度相关（r=0.92），因此 A 导致 B"
- 使用回归系数直接解释为"影响程度"
- 不考虑反向因果、同时因果或第三方混淆变量
- 用相关矩阵热力图直接下因果结论

**真实案例**
2021 年某美赛队发现"消防救援站数量"与"火灾死亡人数"正相关（r=0.78），结论："增加消防站会导致更多火灾死亡"——实为人口密度高的城市同时有更多消防站和更多火灾，混淆变量是人口密度。控制人口密度后，偏相关 r=-0.34（消防站越多死亡越少）。

**诊断方法**
- 自问三句话：① 时间上谁先谁后？② 有没有共同原因？③ 反方向说得通吗？
- Granger 因果检验（时序数据）：检验滞后项是否有显著预测力，p<0.05
- 工具变量法：找一个仅通过 X 影响 Y 的变量 Z，做两阶段最小二乘（2SLS）
- 偏相关分析：控制可疑混淆变量后，相关性是否仍然显著

**修复方案**
- 相关数据用严谨措辞："A 与 B 显著正相关（r=0.XX，p<0.01），**在控制 C 后该相关性减弱/增强/逆转**"
- 因果推断必须用专门方法：DID（双重差分）、RDD（断点回归）、IV（工具变量）
- 若数据不支持因果推断，在结论中显式声明"本研究仅揭示关联性，不证明因果"
- 在论文"局限性"段落说明潜在的遗漏变量偏误

### 1.3 辛普森悖论（Simpson's Paradox）

**症状**
- 分组统计时各组趋势一致为正，但汇总后趋势变成负（或反方向）
- 只汇报整体指标，不进行分组分析
- 数据中存在显著的类别混杂（如不同规模、不同类别的样本）

**真实案例**
某参赛队分析"广告投入与销售额"关系：全部 500 个样本汇总后，回归系数为 -0.15（广告越多销售越差？）。拆分为大客户（300 家）和小客户（200 家）后：大客户组系数 +0.42，小客户组系数 +0.38。真相：大客户投入大但本身销售额高，拉低了整体回归线斜率。

**诊断方法**
- 按关键分组变量（客户类型、地区、时间段等）画分组散点图 + 分组回归线
- 比较分组系数符号与总体系数符号是否一致
- 检查各组样本量是否严重失衡（某组占比 > 70%）

**修复方案**
- 报告结果时必须同时报告分组统计和总体统计，并解释矛盾
- 使用分层回归或固定效应模型，控制组别差异
- 若发现辛普森悖论，在论文中用一张"汇总 vs 分组"对比图展示，这是加分项

### 1.4 幸存者偏差（Survivorship Bias）

**症状**
- 只用"成功"的样本建模，忽略失败或淘汰的样本（典型：只用留存客户数据做流失预测）
- 数据收集过程存在系统性排除（如只分析存活到期末的企业）
- 模型预测精度虚高，因为预测对象和训练对象分布一致但不代表真实总体

**真实案例**
某队做"初创企业成功预测"，选取了 50 家当前的独角兽企业（估值 >10 亿），分析其共同特征（创始人学历、融资轮次等），结论："名校毕业+3 轮以上融资=成功"。但未考虑同期 5000 家同样有这些特征却倒闭的企业。基础率谬误：独角兽概率 ≈ 50/5000 = 1%。

**诊断方法**
- 审查数据收集过程：是否有"结果已知后才纳入样本"的选择机制？
- 计算样本中"成功"的 baseline rate，对比总体中该事件的真实发生率
- 检查数据来源是否有"只看存续/存活"的天然过滤（如上市公司数据库默认排除退市公司）

**修复方案**
- 若无法获取失败样本，在论文中显式声明"本研究存在幸存者偏差，结论仅适用于存活样本，外推需谨慎"
- 若能获取历史全量数据，用 logistic 回归/生存分析（Cox 比例风险模型）处理截断数据
- 若为模拟，人为构造被淘汰样本（negative samples），使正负比例接近真实分布

### 1.5 虚假相关（Spurious Correlation）

**症状**
- 两个明显无关的变量呈现高度相关（|r| > 0.8），无法给出合理因果机制
- 模型引入无实际含义的自变量（如年份编号、ID 序号）并获得高显著性
- 不检查时间序列是否平稳就用 Pearson 相关系数

**真实案例**
经典例：美国 2000-2010 年"冰淇淋销量"与"溺水死亡人数"人均数据显示 r=0.91。若以此建模结论"禁止冰淇淋可减少溺水"显然荒谬。真实原因是"夏季气温高"同时驱动两者（混淆变量）。

此外，1999-2009 年"美国某州离婚率"与"人造黄油人均消费量"的 r=0.99——纯属两个趋势序列碰巧同时下降造成的伪相关。（参见 Spurious Correlations, Tyler Vigen）

**诊断方法**
- 对时序数据先做一阶差分（去趋势），再算差分序列的相关系数——若差分后 r 大幅下降（如 0.9→0.1），原相关系数由共同趋势驱动，不可信
- 计算控制季节/趋势后的偏相关系数
- 用 domain knowledge 判断：两个变量之间是否存在可信的因果链条？
- 若样本量小（n < 30）但 r 很高，警惕：n=10 时随机数据的 |r| 有 5% 概率超过 0.63

**修复方案**
- 相关性分析必须同时报告 Pearson r、p 值、样本量，并讨论可能的混淆变量
- 对时序数据：使用协整检验（Engle-Granger）判断是否为伪回归
- 若发现虚假相关的有趣案例，作为论文亮点讨论"为什么不能只看相关"——展示批判性思维

### 1.6 数据窥探（Data Snooping / p-hacking）

**症状**
- 尝试多种模型/变量组合后，选择 p 值最小的结果报告，但不提及其他尝试
- 反复对同一批数据做显著性检验，不进行多重比较校正
- 先看数据结果再决定假设（HARKing：Hypothesizing After Results are Known）
- 在众多特征中筛选出少数显著特征，然后用同一批数据验证——这本质上是循环论证

**真实案例**
某队研究"影响 GDP 增速的 50 个因素"，逐一做单变量回归，挑出 p<0.05 的 6 个因素报告。但根据 Bonferroni 校正，50 次检验的显著性阈值应为 0.05/50 = 0.001。按此标准，真正显著的只有 1 个。评委若注意到未做多重比较校正，会被视为统计方法使用不当。

**诊断方法**
- 统计论文中报告了多少个 p 值——若 p 值数量 ≥ 检验特征数量的 3 倍，怀疑 p-hacking
- 检查是否有多重比较校正（Bonferroni / Holm / FDR）的说明
- 检查假设是否在数据分析之前提出（若论文先展示数据再提假设，疑似 HARKing）

**修复方案**
- 多重假设检验必须做校正：Bonferroni（严格）或 Benjamini-Hochberg FDR（宽松，适合探索性分析）
- 将数据分为探索集（70%）和验证集（30%）：探索集上找特征，验证集上严格检验，独立报告 p 值
- 若必须做大量探索，使用"训练-验证-测试"三段划分，最终结果只在测试集上报告一次
- 在论文中透明报告："本研究初次检验了 X 个特征，经多重比较校正后，Y 个特征达到显著性水平"

### 1.7 忽略混淆变量（Omitted Variable Bias）

**症状**
- 模型系数大小和符号与常识/文献严重不符
- R² 很高但某个核心自变量不显著（被其他变量吸收了效应）
- 加入一个看似无关的控制变量后，核心系数发生剧烈变化（>30%）

**真实案例**
某队用 OLS 回归分析"教育年限对收入的影响"：β_edu=0.03，p=0.12（不显著）。加入"父母教育年限"作为控制变量后：β_edu=0.12，p<0.001。原来"能力"变量被遗漏，它同时影响教育选择和收入。未加控制变量时的估计是下偏的。

**诊断方法**
- 逐个加入可能的混淆变量，观察核心自变量系数变化率：若 |(β_new - β_old) / β_old| > 0.2，说明遗漏变量偏误严重
- 使用因果图（DAG）画出变量间的关系，识别必须控制的 backdoor path
- 计算 Variance Inflation Factor（VIF）：若某变量 VIF > 10 或 > 5，说明和其他自变量高度共线

**修复方案**
- 在模型中控制领域内公认的混淆变量（即使不显著也保留，以展示控制了）
- 使用 Oster 检验：计算未观测变量的选择偏误程度，评估遗漏变量偏误的严重性
- 若怀疑有不可观测的混淆变量，使用工具变量法或面板数据固定效应
- 在论文**模型假设**中显式列出已控制的和未能控制的混淆变量

### 1.8 过度外推（Over-extrapolation）

**症状**
- 用历史数据（如 2010-2020）训练模型，直接预测远超训练范围的未来（如 2100 年）
- 使用线性/多项式模型外推到自变量取值范围的 2 倍以上
- 预测值违反物理/经济约束（如概率 >1 或 <0、负浓度、负人口）

**真实案例**
某队用 2015-2022 年（8 个数据点）的线性回归预测"某城市 2050 年碳排放量"，得预测值 -3.2 亿吨/年（负排放，相当于预测城市变成巨大碳汇）。实际上该城市近年碳排放在下降，但线性外推 28 年后穿透了零线。该预测无任何现实意义。

**诊断方法**
- 预测区间必须报告置信区间/预测区间，检查区间宽度是否合理
- 检查预测值是否在物理/常识可行域内
- 对预测期做"回溯验证"：用更早数据训练，预测已知的近期数据，对比误差
- 限定外推比例：预测跨度不超过训练数据时间跨度的 50%（如用了 20 年数据，最多预测 10 年）

**修复方案**
- 外推时必须报告预测区间（95% PI），区间越宽表明不确定性越大
- 使用物理约束模型（如 logistic 上限、质量守恒、能量守恒）替代纯统计外推
- 给出短期预测（如 5-10 年），避免长篇大论的超长期预测
- 若必须做长期预测，给出多种情景（乐观/基准/悲观），而非单一数值

## 2 数学与统计错误

### 2.1 p 值误用（p-value Misuse）

**症状**
- 把"p > 0.05"解释为"处理无效"或"变量无关"（实际上只能 fail to reject H0）
- 把"p < 0.05"理解为"有 95% 概率假设成立"
- 盲目追求 p < 0.05，反复尝试不同模型直到 p 值"达标"
- 用 p 值大小比较"显著性程度"（p=0.001 比 p=0.04 "更显著"）

**真实案例**
2022 年某美赛队报告"AHP 一致性比率 CR=0.001，p<0.001，模型非常显著"——这是将 CR 和 p 值混为一谈。AHP 的 CR < 0.1 代表一致性可接受，与假设检验的 p 值完全无关。

**诊断方法**
- 检查 p 值的表述是否准确：不做"p=0.08 → 不显著 → 无影响"的二元判断
- 检查是否同时报告效应量（Cohen's d / η² / 回归系数大小），而非仅报 p 值
- 检查 p 值的使用次数：若论文中出现 ≥10 个独立 p 值未做多重比较校正，高度可疑

**修复方案**
- p 值搭配效应量和置信区间三位一体报告：系数=0.34，95% CI=[0.12, 0.56]，p=0.003
- 准确措辞："在 α=0.05 水平下拒绝零假设"而非"证明假设成立"
- 报告 p 值精确到小数点后 3-4 位（如 p=0.0317），不写 p=0.000
- 对于 p>0.05 的结果，写"未发现统计显著证据"而非"无影响"
- 在大数据（n > 10000）时，几乎所有检验都会 p<0.001，此时 p 值失去参考意义，应重点看效应量

### 2.2 量纲错误（Unit/Dimensional Mismatch）

**症状**
- 模型中同时使用不同单位（如 kW 和 MW 未统一），求和或比较时无意义
- 方程的左右两边量纲不一致（如左边是能量 [J]，右边是功率 [W]）
- 输出结果不带单位，或单位明显荒谬（如 "最优解为 1.5e12 吨"——这相当于全球一年的碳排放量）

**真实案例**
某队建立碳排放优化模型，目标函数中发电成本用"元/kWh"，碳税用"元/tCO2"，约束条件中排放因子用"kgCO2/MWh"。三个单位体系（kWh/tCO2/MWh）交叉使用时，最优解出现数量级错误——预测减排成本为 3 元/吨（实际应为 300-500 元/吨），因为漏了 M→k 的换算因子 1000。

另一案例：人口增长模型 dP/dt = rP，若 r 取 0.02/年 但 dt 用月为步长，模拟 10 年后的 P 为 1.02^120 × P0 ≈ 10.8P0，实际正确值为 e^{0.02×10}×P0 ≈ 1.22P0。

**诊断方法**
- 对每个关键方程做**量纲分析**：左边量纲 = 右边量纲？
- 对每个输出数字做**数量级 check**：结果是否在合理的区间内？（如中国人均碳排放约 7-8 tCO2/年）
- 统一所有计算单位为 SI 基本单位或其一致性派生单位
- 写一段"量纲检查"验证代码：对每个目标函数/约束条件打印量纲

**修复方案**
- 在模型假设中显式声明采用的单位体系（如"本文全部使用 SI 基本单位"）
- 代码中全部使用统一单位（如全部用 kg 不用吨克混用），仅在出图和出表时转换
- 每次输出都打印单位：`print(f"最优减排量 = {optimal:.2f} 万吨CO₂")`
- 在符号说明表中单列"单位"列

### 2.3 数值稳定性错误

**症状**
- 程序运行时报错：ZeroDivisionError, math domain error, RuntimeWarning: invalid value
- 使用了 log(0)、log(负数)、sqrt(负数)、0/0、exp(极大值) 等操作
- 结果中出现 nan、inf、极小负数代替本应为 0 的值（如 -1e-16）

**真实案例**
某队计算熵权法权重时，对归一化后的指标值 p_ij 套用公式 e_j = -k Σ p_ij ln(p_ij)。当某指标的标准差为 0（所有样本该指标值相同）时，p_ij 全等，计算 ln(p_ij) 正常，但后续步骤出现 1-0=1 的中间量，最终产生错误的权重分配。

另一案例：TOPSIS 计算中，理想解距离和负理想解距离当 z_j^+ = z_j^-（该指标在所有方案中无差异）时 d_i^+ 和 d_i^- 可能同时为 0，导致 C_i = d_i^- / (d_i^+ + d_i^-) = 0/0。

**诊断方法**
- 对所有输入数据做"健康检查"：是否有全零列？是否有恒定列？是否有缺失值？
- 在代码中对关键中间变量加 assert/if 检查：`assert x > 0, f"x={x} <= 0 at iter {i}"`
- 检查是否有矩阵接近奇异（np.linalg.cond(A) > 1e10）
- 步长选择是否合理：ODE 求解中步长太大可能导致数值发散

**修复方案**
- 对 log 操作：加极小偏移量 `log(max(x, 1e-10))` 或处理零值 `log(x + eps)` 其中 `eps=1e-12`
- 对除法：`d = max(d, 1e-10)` 或 `np.divide(n, d, where=(d != 0), out=np.zeros_like(n))`
- 对 sqrt：`sqrt(max(x, 0))` 并注释说明如果 x 应为 0 但出现微小负数则取 0
- 对矩阵求逆：使用 `np.linalg.lstsq`（最小二乘）替代 `np.linalg.inv`，或用 `np.linalg.pinv`（伪逆）
- 在 ODE 求解中使用变步长方法（如 RK45），设置合理的 atol=1e-8, rtol=1e-6

### 2.4 忽略多重共线性（Multicollinearity Neglected）

**症状**
- 回归系数的符号与直觉/理论相反（如"教育年限"的回归系数为负）
- 系数标准误非常大，t 统计量很小，整体 F 检验显著但各变量不显著
- 加入或删除一个变量后，其他变量的系数剧烈变化
- OLS 回归的 R² 很高，但主要变量都不显著

**真实案例**
某队建立"房价影响因素"回归模型，自变量包含"房屋总面积"和"居住面积"。OLS 结果：总面积系数 = -2.5（负的？），居住面积系数 = +3.8，两个都 p>0.05，但模型 R²=0.87。问题：总面积和居住面积的相关系数 r=0.96，属于严重共线。删除总面积后，居住面积系数变为 +1.2，p<0.001。模型从"看起来无用"变成"简洁有力"。

**诊断方法**
- 计算所有自变量的相关系数矩阵，任意两个自变量 |r| > 0.8 即是危险信号
- 计算 Variance Inflation Factor：VIF > 10 强烈共线；VIF > 5 需要关注
- 观察系数标准误：若某系数 SE 远大于系数本身（|coefficient/SE| < 1.96），可能受共线影响
- 做逐步回归：看变量被加入/移除的顺序和系数的稳定性

**修复方案**
- 删除共线变量中理论重要性较低的一个，优先保留解释力更强/更直接的那个
- 合并共线变量为主成分（PCA），但需解释主成分的含义（扣分风险：可解释性下降）
- 使用 Ridge 回归（L2 正则化）：自动压缩共线变量系数，α 通过交叉验证选
- 收集更多数据（增大样本量可缓解共线性影响）
- 若两个变量本质测量同一概念，构造复合指标（如加权平均）

### 2.5 非正态数据强行用正态方法

**症状**
- 数据明显偏态（收入数据右偏、比率数据双峰）但直接做 t 检验/ANOVA
- 不做正态性检验就上参数检验方法
- 使用 Pearson 相关分析明显非线性的单调关系

**真实案例**
某队分析"城市 PM2.5 浓度影响因素"，使用 Pearson 相关系数矩阵分析各气象因子与 PM2.5 的关系。但 PM2.5 浓度分布严重右偏（skewness=2.3，峰度=8.1），且与风速的关系为明显的非线性（低风速时 PM2.5 急剧升高，高风速时趋于平稳）。用 Pearson r 分析时，风速 r=-0.31（弱相关），改用 Spearman ρ 后 ρ=-0.71（强单调相关）。结论完全不同。

**诊断方法**
- 对因变量做直方图 + Q-Q 图，视觉判断正态性
- Shapiro-Wilk 检验：n ≤ 2000 时有效，p < 0.05 拒绝正态假设
- Kolmogorov-Smirnov 检验：n > 2000 时使用
- 计算偏度（skewness）和峰度（kurtosis）：|skewness| > 1 或 |kurtosis-3| > 2 视为严重偏离

**修复方案**
- 非正态连续数据：用 Mann-Whitney U（代替 t 检验）、Kruskal-Wallis（代替 ANOVA）
- 非线性单调关系：用 Spearman ρ 或 Kendall τ 代替 Pearson r
- 对偏态数据取对数变换（log-transform）或 Box-Cox 变换后检验正态性
- 若数据量足够（n > 30 每组），可根据中心极限定理使用 t 检验，但需要显式说明
- 报告时同时给出参数检验和非参数检验结果，展示鲁棒性

### 2.6 统计显著性与实际重要性混淆

**症状**
- 论文中仅用"p < 0.001"来论证变量"非常非常重要"
- 不报告效应量（effect size），仅报告 p 值
- 在大样本（n > 10000）时将微小的实际差异（如平均分差 0.1 分）描述为"显著改善"

**真实案例**
某队分析"两种教学方法对学生成绩的影响"：A 组平均分 75.2，B 组平均分 75.6。n=5000 每组，t 检验 p=0.003。结论："B 教学方法显著优于 A"。但实际差异仅为 0.4 分（满分 100），Cohen's d=0.06。按 Cohen 标准，d=0.2 才是小效应——0.06 几乎可以忽略。该队混淆了"统计显著"和"实际显著"。

**诊断方法**
- 报告 p 值时必须同时报告效应量：连续变量用 Cohen's d 或 Hedges' g，分类变量用 Cramer's V 或 φ 系数
- 计算置信区间：95% CI 的宽度反映了估计精度
- 自问："如果我是一个决策者，这个效应的大小够不够让我改变做法？"

**修复方案**
- 强制规则：每个假设检验必须报告 (a) 检验统计量 (b) p 值 (c) 效应量 (d) 95% CI
- 效应量判断标准（Cohen 经验法则）：d=0.2 小，0.5 中，0.8 大；η²=0.01 小，0.06 中，0.14 大
- 在论文"结果分析"中加入专门的"实际意义"评估段

## 3 论文写作错误

### 3.1 摘要无量化结果

**症状**
- 摘要全是"本文建立了……模型""采用了……方法"，没有具体数值
- 所有句子都以"本""We""The paper"开头
- 摘要 500 字但找不到一个数字或百分号

**真实案例**
某队摘要：
> "本文针对货运碳排放问题，建立了综合评价模型和优化模型，运用了层次分析法和遗传算法，得到了一些有意义的结果。"

评委打分 4/10（摘要项）。原因：不知道具体做了什么、结果是什么、误差多少、比现有方法好多少。

正确示范：
> "本文建立三阶段模型分析货运碳排放。问题一，TOPSIS-熵权法评价 15 个城市，邯郸得分最高（0.7637），最差的仅 0.2134，区域差异达 3.58 倍。问题二，非线性规划优化货运结构，公路占比从 74% 降至 52%，碳排下降 28.7%（3680 万吨）。问题三，多目标 GA 优化 2030 年投资方案，单位减排成本 127 元/tCO2，比当前碳市场均价低 34%。"

**诊断方法**
- 数摘要中的数字（含百分号、小数、带单位数字）：少于 4 个即不及格
- 检查摘要是否覆盖"用什么方法 + 得到什么结果 + 结果数值多少"三个要素
- 自问：如果评委只看摘要（他们通常只看摘要），能知道你的核心贡献吗？

**修复方案**
- 强制规则：摘要中每小问至少给出 1 个具体数字（最优值/误差率/排名/提升幅度）
- 摘要结构模板：背景（1 句）→ 问题概述（1 句）→ 方法+结果（每问 1-2 句，含数字）→ 创新点（1 句）→ 结论（1 句）
- 在建模结束后重新写摘要，因为此时你才有确切的数字

### 3.2 图表无解读文字

**症状**
- 论文中出现"如图 3 所示"的裸引用，没有说明读者应该从图 3 中读出什么
- 图表仅作为"装饰"，对论证无贡献
- 图表的 caption 泛泛（如"模型结果"），不写明关键发现

**真实案例**
某队论文中插入了一张热力图，caption 为"图 5：相关性分析热力图"，正文仅写"如图 5 所示"。评委无法判断：(1) 作者自己理解了这张图吗？(2) 发现了什么关键信息？(3) 这对后续建模有什么指导？

正确示范：
> "图 5 展示各指标间的 Spearman 相关系数矩阵。值得注意的是，GDP 增速与碳排放强度呈显著负相关（ρ=-0.72，p<0.001），说明经济增长伴随碳效率提升——这一脱钩现象验证了环境库兹涅茨曲线假说，因此我们在 §4.3 的预测模型中引入 GDP 增速作为控制变量。"

**诊断方法**
- grep 所有 `\ref{fig:` 引用，检查每条引用前后是否有 1-2 句实质性解读
- 检查 caption 中除了图表标题外，是否有"关键发现"的一句话总结
- 自问：删掉这张图，论文的论证链是否断裂？如果不断裂，说明图没被用在论证中

**修复方案**
- 每张图的 caption 格式："图 X：[图表名称]。关键发现：[一句话总结]。"
- 正文中的图引用必须包含：指出关键特征 + 解释原因或推论 + 连接后续模型决策
- 用检查清单：该图展示了什么趋势/模式？该模式说明什么？该发现如何影响下一步？

### 3.3 模型假设无依据

**症状**
- 假设列了一堆（5-8 条），但每条后面没有说明"为什么可以这样假设"
- 假设与假设之间相互矛盾（如假设"市场完全竞争"又假设"政府定价调控"）
- 假设过于理想化，与现实明显不符却不讨论影响

**真实案例**
某队假设清单：
> "假设 1：所有决策者完全理性。假设 2：所有信息完全对称。假设 3：市场无交易成本。"

没有任何依据说明。评委意见："假设过于理想化且无依据，缺乏现实可行性讨论。"扣 10 分。

**修复方案**
- 每条假设遵循三段式：(1) 假设内容 (2) **依据**（为什么合理？引用文献/常识/数据分析） (3) **放宽后果**（如果放松该假设，模型结果会如何变化？预计偏差方向？）
- 示例：
  > **假设 3**：电网碳排放因子在预测期内保持 2023 年水平（0.581 tCO2/MWh）。
  > **依据**：根据国家能源局规划，煤电占比从 2023 年的 58% 降至 2030 年的 45%，但新建可再生能源的不确定性使未来因子难以精确估计，取定值简化。
  > **放宽后果**：若实际因子更低（如 0.45），本模型估算的减排效果将被**低估**约 23%，即使如此，结论方向（减排有效）不受影响。
- 核心假设（影响结论方向的）做灵敏度分析，展示假设变化对结论的鲁棒性

### 3.4 参考文献格式混乱

**症状**
- 同一篇论文中混用 [1]、(Author, 2020)、\cite{} 多种引用格式
- 参考文献列表格式不统一（有的有 DOI，有的没有；有的全大写，有的首字母大写）
- 引用了不可靠的来源（百度百科、个人博客、维基百科）

**真实案例**
某美赛队参考文献列表中包含 3 个百度百科链接和 2 个知乎文章。评委意见："学术规范不足，应优先使用期刊论文、官方报告等权威来源。"

**诊断方法**
- 参考文献来源抽检：是否有 ≥3 个不可靠来源（百科/博客/论坛）？
- 格式一致性抽检：前 5 条和后 5 条的格式是否完全一致？
- 中英文文献是否分别用 [中] 和 [英] 或其他标记区分？

**修复方案**
- 强制规则：参考文献 60% 以上必须来自期刊论文、会议论文、官方统计报告
- 优先使用知网/Google Scholar/Web of Science 检索
- 使用 BibTeX 统一管理引用（推荐 `natbib` 宏包，`\citep{}` / `\citet{}` 自动格式化）
- 每条参考文献至少包含：作者、标题、期刊/来源、年份、卷期页码（或 DOI/URL），格式统一
- 中文队：引用 ≥2 篇近 3 年的相关中文学术期刊文献（证明了解国内研究现状）

### 3.5 结论超出数据与模型支持范围

**症状**
- 用 n=30 的小样本做回归，结论宣称"具有普遍适用性"
- 用一个城市的案例，结论推广到"全国/全球"
- 模型的假设本身就有限制（如线性假设），结论却忽略这些限制做绝对化表述

**真实案例**
某队用 2019 年的单一年份截面数据（分析 30 个城市），结论："本文建立的电力碳排放预测模型适用于中国所有地级市，可直接用于各省制定碳达峰路径。"——单一年份数据无法验证跨时间泛化性；30 个样本无法代表 300+ 地级市多样性。评委评为"结论过度推广"。

**修复方案**
- 结论段必须有专门的"适用范围和局限性"小节
- 使用限制性措辞："在本研究的数据范围和模型假设下……""结论对 [特定条件] 的情况是否适用有待进一步研究"
- 避免绝对化词汇："证明""必定""完全"→ 替换为"表明""倾向于""在给定假设下"
- 结论语言模板："本研究基于 [XX 个城市 / XX 年数据 / 假设 XX]，结果表明……。这些结论在 [哪些条件下] 是有效的，其向 [哪些更广泛的情境] 的推广需要 [什么额外验证]。"

## 4 代码实现错误

### 4.1 随机种子未固定

**症状**
- 每次运行代码得到不同的数值结果
- 论文中的关键数字无法复现（他人跑相同代码得到不同答案）
- 模型训练结果不可复现（今天跑是 92.3%，明天跑是 89.7%）

**真实案例**
某队提交的论文声称"GA 算法求得最优解为 347.2 万吨"，评审专家运行其公开代码后得到 352.8 万吨。误差虽小（1.6%），但因随机种子未固定，评审无法验证论文结果的正确性，被标注"不可复现"扣分。

**诊断方法**
- `grep -n "seed|set_state|random_state" code/*.py`：检查是否每个使用随机数的文件都设置了种子
- 运行代码 3 次，对比 stdout 中的 3 个以上关键数字是否完全一致
- 检查使用了 `np.random`、`random`、`tf.random`、`torch.manual_seed` 的每个位置

**修复方案**
- 每个文件开头统一设置所有随机种子：
  ```python
  import numpy as np
  import random
  SEED = 42
  np.random.seed(SEED)
  random.seed(SEED)
  # TensorFlow:
  # tf.random.set_seed(SEED)
  # PyTorch:
  # torch.manual_seed(SEED)
  ```
- 在论文附录中注明使用的随机种子值（SEED=42）
- sklearn 模型参数中 `random_state=SEED` 统一传入
- GA/PSO/SA 等启发式算法：保存最优解文件（.npy 或 .pkl），最终结果从文件读取而非重新跑

### 4.2 硬编码路径

**症状**
- 代码中出现 `C:\Users\张三\Desktop\数据.csv` 或 `/home/zhangsan/data.csv`
- 代码在不同电脑 / 目录下运行报 FileNotFoundError
- 代码中写死绝对路径，项目移动后全部失效

**真实案例**
某队提交的 `solve_q1.py` 中：
```python
df = pd.read_csv("C:/Users/admin/Desktop/比赛/data.csv")
```
评委的代码审计脚本在 Linux 服务器上运行，路径格式不匹配，直接报错，该问的代码验证项 0 分。

**诊断方法**
- `grep "C:\\\\|/home/|/Users/" code/*.py`：搜索类似模式的硬编码路径
- 检查数据读取路径是否使用相对路径或 `os.path.join`
- 检查代码中是否有任何依赖本地绝对路径的操作

**修复方案**
- 使用相对路径 + 项目根目录定位：
  ```python
  import os
  PROJECT_ROOT = os.path.dirname(os.path.dirname(os.path.abspath(__file__)))
  DATA_DIR = os.path.join(PROJECT_ROOT, "data")
  df = pd.read_csv(os.path.join(DATA_DIR, "raw_data.csv"))
  ```
- 所有数据文件统一放在 `data/` 下，代码引用时用相对路径 `../data/` 或上述 PROJECT_ROOT 方法
- 在 README.md 中说明项目的目录结构和运行方式
- windows/linux 路径分隔符兼容：全部使用正斜杠 `/` 或用 `os.path.join`

### 4.3 无异常处理

**症状**
- 数据读取失败时程序直接崩溃，输出一长串 traceback
- 优化算法不收敛时陷入死循环，无超时机制
- 计算结果出现 nan/inf 时不检查也不警告，继续传给下游计算

**真实案例**
某队的非线性规划求解中，scipy.optimize.minimize 返回 status=2（超过最大迭代次数），但代码未检查 `result.success`，直接使用 `result.x`（此时是最后一次迭代的不可行解，违反约束），后续计算全部基于错误结果。

**诊断方法**
- 检查代码中是否有 `try-except` 块或 `assert` 检查
- 检查优化/求解函数后是否有 `result.success` 判断
- 检查数据加载部分是否有格式/完整性验证

**修复方案**
- 数据加载必加异常处理：
  ```python
  try:
      df = pd.read_csv(os.path.join(DATA_DIR, "data.csv"))
      assert len(df) > 0, "数据为空"
      required_cols = ["city", "year", "carbon"]
      missing = set(required_cols) - set(df.columns)
      assert not missing, f"缺少必要列: {missing}"
  except Exception as e:
      print(f"[FATAL] 数据加载失败: {e}")
      sys.exit(1)
  ```
- 优化结果检查：
  ```python
  result = minimize(fun, x0, bounds=bounds, constraints=cons, options={'maxiter': 5000})
  if not result.success:
      print(f"[WARN] 优化未收敛: {result.message}, status={result.status}")
      print(f"        当前目标值={result.fun:.4f}, 请检查后手动修正")
  ```
- 中间结果检查：
  ```python
  assert not np.any(np.isnan(X)), "X 包含 NaN，停止计算"
  assert not np.any(np.isinf(X)), "X 包含 Inf，停止计算"
  ```

### 4.4 数据泄露（Data Leakage）

**症状**
- 先用全部数据做标准化/归一化，再分成训练集和测试集
- 测试集上表现异常好（准确率 99%+），但部署后效果极差
- 训练集和测试集的预处理使用了相同的变换参数（如在全部数据上拟合 StandardScaler）

**真实案例**
某队做碳排放预测：用全部 2000-2023 年的数据计算均值和标准差做标准化，然后划分训练集（2000-2018）和测试集（2019-2023）。因为测试集的标准化参数是"偷看"了测试数据本身计算出来的，测试集上的 RMSE 虚假偏小约 35%。正确做法是只用训练集计算参数，再用同样参数变换测试集。

**诊断方法**
- 检查数据预处理代码：标准化/归一化/缺失值填补是否发生在 train-test split 之前？
- 检查时间序列预测：是否用到了"未来"信息（如 lag feature 计算时用了后面的值）？
- 检查交叉验证：是否先做了特征选择再交叉验证（应该每一步交叉验证内重新做特征选择）？

**修复方案**
- 铁律：先划分，再预处理——任何使用数据统计量的变换必须**仅在训练集上 fit**，然后 transform 测试集
  ```python
  from sklearn.model_selection import train_test_split
  from sklearn.preprocessing import StandardScaler

  X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.3, random_state=SEED)

  scaler = StandardScaler()
  X_train_scaled = scaler.fit_transform(X_train)   # fit ONLY on train
  X_test_scaled = scaler.transform(X_test)          # use train params
  ```
- 对时序数据：永远按时间顺序划分（不随机打乱），训练集时间 < 验证集时间 < 测试集时间
- 在交叉验证中使用 `Pipeline` 确保预处理在每折内部重新执行
- 特征选择也必须在交叉验证内部做，不能在交叉验证前用全部数据做特征选择

### 4.5 复制粘贴导致变量名错误

**症状**
- 代码运行到一半报 `NameError: name 'xxx' is not defined`
- 输出结果和预期完全不符，排查半天发现某处变量名是上一步的旧名
- 同一段逻辑复制到不同问的代码中，变量名没改，导致结果互相覆盖

**真实案例**
某队的 `solve_q2.py` 从 `solve_q1.py` 复制了 AHP 权重计算部分，但 `q1_data` 的变量名未改为 `q2_data`，结果计算出来的权重实际上是 Q1 值，但标注为 Q2 结果写入论文。对抗审稿的自动验证脚本发现"Q2 权重与 Q1 权重完全一致（差异 < 1e-10）"，标记为重大错误。

**诊断方法**
- 逐文件 grep 每个变量名，确认其定义-使用链条一致
- 对比 `solve_q1.py` 和 `solve_q2.py` 的 diff，检查复用部分的变量名是否已更新
- 运行代码后，随机抽查 3 个关键中间变量的值，手动验算是否合理

**修复方案**
- 公共逻辑提取为函数放到 `utils.py`，各问代码 import 调用而非复制粘贴
  ```python
  # utils.py
  def ahp_weight(pairwise_matrix, cr_threshold=0.1):
      """AHP 权重计算，返回 (weights, CR, is_consistent)"""
      ...
      return weights, cr, is_consistent

  # solve_q1.py
  from utils import ahp_weight
  weights_q1, cr1, ok1 = ahp_weight(A_q1)

  # solve_q2.py
  from utils import ahp_weight
  weights_q2, cr2, ok2 = ahp_weight(A_q2)
  ```
- 每个问的求解代码开头打印显式的标识信息：
  ```python
  print("=" * 60)
  print(" QUESTION 2 SOLVER — 货运结构优化")
  print("=" * 60)
  ```
- 使用有意义的变量名（`weights_q2` 而非 `w`），凡是跨文件复制的必须全文检查变量名一致性
